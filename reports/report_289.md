### Necessary production paths

- **Initialization, preferences and tab views.** The resolver establishes installation identity. `pty_open` still verifies the interpreter for each new process because saved paths can refer to different installations or change between launches. Restored tabs retain exact roots and recovery records. The spare reuses its live PTY when promoted and is replenished once. Selecting a tab changes unread state, attachment routing and viewport in memory. A mount can legitimately begin image discovery or resize the PTY. Preference writes retain the cross-window freshness check, and workspace storage already suppresses byte-identical writes.
- **Control transport and terminal.** `runner_observe` retrieves a native snapshot. Native authenticated `observe` is a separate request with one outstanding poll and a nominal one-second cadence. Hub's 500 ms idle and 50 ms foreground schedules consume receipts and connection state, while several shorter wait loops inspect memory. PTY output acknowledgements bound buffers, input writes preserve parser order, and the resize and close paths retain native geometry and exact process settlement. Inactive tabs still receive observations.
- **Options, settings and external services.** Option popovers read memory and do not request fresh pages on open or tab switch. Change-driven invalidation and bounded refresh cover registry, account and model changes without a Hub notification. Destination options stay account-scoped. Runner signs the plan and revalidates authority, root and availability at mutation. Final inspection retains setup, effective settings and partial or uncertain outcomes. Runner may read profiles, target registrations and Direct preferences and use Provider-owned model or policy services. For Codex, model discovery can use the App Server `model/list` RPC. Hub sends no direct Provider HTTP requests. Provider RPC and outbound network counts remain separate from Hub IPC and authenticated Runner counts.
- **Instruction and status.** Typed slash commands, structured interaction, Work submission, Brief staging and Run invocation keep separate canonical admissions. Brief and Work status observe the exact original request. Work inventory remains cursor-based and continues after terminal outcomes and in inactive tabs, so short sequential terminal work and late completion remain discoverable. Reuse, restart and close retain fresh authority, inventory and owned termination checks.
- **References, previews and media.** Explicit native pickers are demand-driven. Drag/drop and paste stage local candidates, and preview owners reuse acquired bytes across view modes. Reference pagination, two stable samples, exact removal IDs and post-registration checks protect work against crossed or changing references. Native clipboard validation and independent file readback establish byte readability for Runner. Generated-image inventory is throttled to the active view because Runner supplies no push signal. Verified chunk reads and explicit Refresh preserve byte checks, and reused sessions retain the existing attribution restriction. PDF worker resources are bundled with the app.
- **Recovery, restart and logging.** Recovery checks canonical eligibility and current connected context before adoption and retains original identity on uncertainty. Context capture remains bounded and independent of selection. Restart joins exact close/exit before replacement. Hub logs serialize restore, append and retention, including re-reading and parsing current disk contents to preserve existing records and surface damage. The hourly retention timer is local filesystem maintenance. No request tracing was added.

The exact Target policy index was unavailable in the context manifest. Runner production source supplied read-only contract evidence.
