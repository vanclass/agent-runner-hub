## 3. Work Summary
- Established the existing ownership chain before implementation: RunnerSession owns terminal/input/control lifetime, RunnerSessions owns visible identity and registry, RunnerWorkspace owns persisted records, and the native Sessions registry/Windows Job Object owns PTY processes and descendants. No second Runner backend or process manager was introduced.
- Added RunnerSpare as the single hidden preparation owner. Its generation-bound, serialized operation admits at most one hidden session, bounds launch plus readiness, drains/parses output through the existing terminal, rejects unresolved canonical readiness, and joins exact owned cleanup before replacement. Cleanup failure blocks subsequent prewarming and gives close/reopen guidance.
- Shared the existing native installation resolver through runnerInstallation.ts. Restart treats a saved path only as resolver input. Workspace loading precedes spare callbacks, so startup cannot overwrite saved tabs. Late resolver, control and PTY results cannot revive a disposed spare or publish a changed installation.
- Exposed RunnerSessions.promoteSpare(): RunnerSession and a read-only spareSnapshot. Promotion synchronously rechecks freshness/readiness, transfers the existing session, and assigns UUID/name/creation order under the workspace owner. PTY/control identity, terminal protocol and output history survive; exactly one replacement is then prepared. Refusal throws HubError. Future Single Entry code can consume this interface and use existing reservation/configuration/delivery owners without managing another spare.
- Kept the hidden session outside the visible registry and RunnerWorkspace records. The selected representation retains an unassigned tab record until promotion; creating a fake persisted tab or a duplicate native lifecycle was rejected. Creation, parsing, promotion, persistence handoff and disposal use one session object; terminal editing, clipboard/reference operations and current submission behavior remain with their existing owners.
- Preserved New Runner and current Single Entry allocation/submission paths; Single Entry does not yet consume promotion. English/Korean preparation and actionable failure messages appear beside installation verification. Moved status out of the global shell after responsive checks exposed reduced terminal space.
- Existing specification updated: docs/implementation_specs/runner_terminals.md owns the spare/readiness/promotion contract; IMPLEMENTATION_SPEC_INDEX.md routes its new source owners, and hub_preferences.md links the current owner. No new competing feature document was created. The exact AgentRunnerHub PROJECT_POLICY_INDEX.md lookup was absent; no project-specific policy leaf applied.
