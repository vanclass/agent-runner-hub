## 3. Work Summary
- Added RunnerWorkspace.ts as the single Hub-owned persistence boundary: local-storage key agent-runner-hub.workspace.v1, version 1, and an explicitly projected tabs array. Each record contains stable Hub UUID, display name, positive creation order, verified installation root, launch-on-open intent and optional last authenticated target/run-mode/workflow context. A single setItem replaces the manifest atomically on relevant changes; failures retain the last commit and show a warning.
- RunnerSessions owns current session state and composes validation/restoration before native launch. Valid records are sorted independently, duplicate IDs/orders and malformed records are diagnosed, and unsupported/truncated schemas are retained without overwriting. Each running/starting record opens a fresh native PTY/control session; ended tabs remain dormant. Disposal suppresses exit-driven manifest changes while native ownership handles cleanup. React StrictMode effect replay is idempotent.
- RunnerRecovery.tsx presents saved context separately from fresh process readiness and requests only the current canonical /recover flow. Runner owns candidate discovery, terminal selection/confirmation, admission and continuation. The public v1 projection exposes no logical Task/Issue/workload identity or authoritative successful work-recovery receipt; none is invented. Private control identities/keys, PIDs/handles, credentials, buffers, drafts, pending Single Entry assignments and uncertain commands never enter the manifest.
- Selected a metadata projection rather than serializing live session objects or maintaining a second process registry. Durable record writes remain with each session and the persistence boundary; Hub composes selection and notifications. Startup uses independent existing launch operations with deterministic registry order; no scheduler, dispatch policy, queue, automatic command replay, private Runner modification or macOS launch enablement was added.
- Updated the existing runner_terminals.md specification and its root route, plus directly affected PRD/architecture summaries. The exact AgentRunnerHub project-policy index was absent at the canonical Target environment; no project-specific policy was loaded.
