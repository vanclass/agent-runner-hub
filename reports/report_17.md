## 3. Work Summary
- Final Native Feature API: `features.rs` owns the implemented feature name/version/capability surface and typed admission/results; `session_config.rs` owns strict inspect/plan/apply requests and sanitized typed replies. Unsupported operations/versions are not exposed. No plugin engine, server or separate authentication was added.
- Native ownership: `control.rs` retains authenticated exact PID/session/connection matching, monotonic request IDs, FIFO and completion correlation. Explicit request kinds prevent session_config completions from becoming observations. `control_windows.rs` retains private pipes, nonblocking worker and cleanup. Tauri checks window/session ownership; feature admission clones the client before waiting, releasing the session mutex.
- TypeScript ownership: one `RunnerConfigService` belongs to each `RunnerControl`/RunnerSession. Its narrow transport port owns no PTY or preferences. Drafts, catalogs, plans, receipts and application history remain session-local. Identity binds only after authenticated readiness; native generation plus PTY session fences startup, tab switches, closed instances and late results.
- Inspect uses API v1 and reads canonical current/effective/next settings, Root, availability, constraints and actual stable candidate IDs. Optional account inspection reads that destination catalog without switching accounts. Account/model/reasoning/tier selections are validated against that exact destination catalog.
- Catalog collection starts at offset zero. It retains instance/account identity, model_options_account, revision, options_revision and totals; subsequent pages send the first token unchanged and validate offsets, exact lengths, progress, stable totals/modes/evidence and duplicate IDs. Only terminal null publishes a complete list. Any mismatch, stale/failure/unavailable catalog, disconnect or missing completion discards it; explicit refresh restarts instead of merging attempts.
- Legacy feature v1 without options_revision can expose only a provably complete single page; unguarded multi-page selections stay unavailable. Missing/unsupported session_config leaves the existing terminal menus, v1 commands, references, images and PTY available.
- Plan carries desired settings and changes nothing. Apply requires an explicitly reviewed ready plan and copies its exact desired/revision/plan_id; options_revision is never sent to plan/apply. Draft edits invalidate plans; an immediate pre-apply inspect rejects changed revision. Runner still performs its own fresh authorization and per-commit checks. Context release/Brief discard stays with the official Runner terminal.
- Only completed owner results establish commits. Per-setting success/rejected/cancelled/failed/unknown/not_attempted and sequential stops are preserved. Earlier commits survive partial failure and failed final inspection; no rollback or inference from equal current values occurs. Missing receipts remain unknown without replay. A late authoritative receipt can resolve delivery uncertainty only for its exact request in the same live instance.
- Long waits: Runner's catalog owner permits up to 32 RPC pages with 10-second per-page waits; planning adds policy checks and apply repeats validation around commits. Native FIFO-head limits are inspect 420s, plan 600s and apply 1800s, with bounded frontend delivery grace. Followers receive their own interval after preceding completion. Queued is admission, not processing/start/success; terminal pending-interaction retains its owner. Worker I/O and other Runner workers remain independent. Outgoing byte positions distinguish proven no-send from partial/full unconfirmed transmission.
- Existing defaults explicitly map target registry identities, model IDs/reasoning and separate tier, and canonical mode through verified candidates. A persisted profile label never recovers an account identity, even when the current label matches; it is displayed unresolved for explicit account selection. The reverse safe projection checks current evidence. preferences.v1, workspace/installation stores and malformed-data preservation are unchanged; no migration or persistent plan/token/identity/result store was added.

All Hub labels, progress, errors/help and accessibility text use English/Korean i18next keys; raw IDs/paths/commands/diagnostics stay original. Light/Black variables and session drafts survive language/tab changes. Expanded settings keep terminal/composer reachable.
